# Agent 对话为什么会丢失关键问题

> 日期：2026-09-15
>
> 状态：现象分析与开放讨论
>
> 来源：一次实际使用体验的讨论，以及相关一手研究的核验。本文的分类和解释属于分析框架，尚未通过具体对话样本验证，也不构成已实现的产品方案。

## 核心判断

与 Agent 对话时，问题会不断分岔、重组和暂停；聊天记录则按时间顺序累积。如果缺少对问题关系、处理状态和后续意图的维护，就可能出现这样的体验：当时讨论得很充分，结束后却说不清还有哪些关键问题值得继续。

这份分析以一个使用反馈为起点：

> 一开始可能只想聊一个话题，过程中也会发现新的问题，逐渐聊成多个话题。聊完以后，一些关键问题点就丢失了。

需要分别理解：哪些内容没有留下，哪些内容虽然留下却难以找回，以及哪些问题失去了继续推进的线索。

## 一、人和 Agent 的交互如何发展

下面按交互目的分类，用于辨认对话中的变化，不代表不同人群的使用占比。

| 交互方式 | 对话怎么发展 | 容易遗留什么 |
| --- | --- | --- |
| 明确问答 | 带着具体问题获得答案，再追问细节 | 一次提出多个问题，其中部分没有被回答 |
| 逐步澄清 | 从模糊感觉出发，通过讨论识别真正的问题 | 最初的不满、约束或判断依据被后来的表述覆盖 |
| 围绕目标展开 | 一个目标涉及用户、方案、成本、技术等多个方面 | 部分方面聊得很深，其他方面没有继续 |
| 探索与比较 | 尝试不同解释、方案和假设，不断分岔 | 备选方案、排除理由和值得回来探索的方向 |
| 边聊边执行 | 分析后开始行动，执行中发现依赖或新问题 | 子问题处理完了，原问题没有接着推进 |
| 自由联想 | 某个回答触发新的兴趣或疑问，临时转向 | 当时觉得重要、准备稍后再问的念头 |

同一个人、同一段对话，可以连续切换这些方式。开始是在问答案，中途变成梳理问题，随后进入方案讨论，最后又开始执行。

一个问题可能跨越多个会话，一个会话也可能承载多个问题。因此，会话边界和问题边界并不重合。

类似体验也出现在其他用户研究中。CanvasConvo 的前测记录了长线程难以掌握全貌、拆分聊天造成上下文碎片化的反馈。该研究包含 24 名多数熟悉 LLM 的参与者，属于短期探索研究，不能据此估计所有用户的发生率。[研究原文 §5–6.1](https://arxiv.org/html/2605.15848v1#S5)

## 二、新问题从哪里产生

以一个假设场景为例：

1. 想讨论“怎样提高新用户激活率”。
2. 先讨论“激活应该怎么定义”。
3. 发现“现有数据可能不可靠”。
4. 开始排查埋点。
5. 最后把埋点修好了。

这条路径有合理的依赖关系：后面的问题是前面问题的前置条件。但埋点修好后，“怎样提高激活率”仍然需要继续；过程中提到的“优先改善哪些用户的体验”，也可能还没有展开。

对话中的转向至少包括以下几种：

- **向下深入**：为了回答 A，需要先解决 A 的细节。
- **横向比较**：讨论方案 A 时，想到方案 B。
- **重新定义**：聊着聊着，发现原来的问题需要改写。
- **独立联想**：由 A 想到一个有价值、但可以单独讨论的 C。
- **回答引出分支**：Agent 给出多个角度，用户接着其中一个聊下去。

这些转向的后续处理不同。前置问题解决后需要回到上层，备选方案需要比较，原问题被重新定义后可能应该结束。问题之间也可能交叉关联，未必能完全表示成一棵树。

**当前正在聊哪个问题，并不能说明其他问题已经处于什么状态。**

## 三、“关键问题丢了”的六种情况

### 1. 念头没有进入对话

读 Agent 回答时，同时想到三个问题，先问了其中一个，另外两个后来忘了。

这些念头尚未被表达，聊天记录无法完整保存它们。后续总结也不能可靠还原用户未说出的想法。

### 2. 问题提出了，但没有展开

用户提到“这里还有一个风险”，随后双方继续讨论其他内容。风险留在原文里，却没有再次进入注意范围。

### 3. 问题展开了，但没有收尾

双方讨论了几轮，随后转向。后来不清楚它是已经解决、暂时搁置，还是还缺证据。

“讨论过”“已有回答”“问题已解决”需要分别辨认。

### 4. 结论留下了，理由和前提模糊了

记得当时选了方案 B，却忘了为什么没有选 A，以及这个选择成立的条件。

这会影响后续复用：条件变化后，旧结论可能仍被沿用；已经排除过的方案也可能再次被重复讨论。

### 5. 记得存在，但找回成本太高

知道之前聊过一个重要的点，却想不起关键词，也不知道在哪段记录里。最终重新聊一遍，或者放弃寻找。

这时需要辨认的是内容的可找回性，而非仅检查消息是否保存。

### 6. 内容找得回来，却不知道怎么继续

能找到当时的讨论，但不清楚下一步该验证什么、等待什么，或者回到哪个主问题。

这些损失可能叠加发生。仅根据最初反馈，值得优先核验的是第 2、3、6 类；现有材料还不足以判断哪一类占主导。

## 四、形成这个现象的几层机制

### 人需要同时维护当前思路与后续意图

从 A 转去讨论 B 时，人需要理解和推进 B，同时记住 A 还没结束，以及何时回到 A。

关于任务中断的实验研究，将“之后记得恢复原任务”视为前瞻记忆，即记住未来要做的事。出版社摘要报告了两项分别操纵意图编码和提取条件的实验。将这一机制映射到话题切换，是对当前场景的推断；原研究没有测试 Agent 对话。[Interruptions create prospective memory tasks](https://onlinelibrary.wiley.com/doi/10.1002/acp.1441)

### 消息顺序与问题关系承载不同的信息

记录可以完整保存“先说 A，再说 B，然后说 C”，但继续工作时需要知道的可能是：B 是解决 A 的前提，C 是暂时保留的备选，A 还没有结论。

这些关系如果只隐含在文字里，每次回来都需要重新理解。

Sensecape 的研究中，12 名参与者分别完成两项各 20 分钟的探索任务，在其系统中更频繁回访旧信息。基线已经包含聊天与笔记画布，因此不能把结果简化为画布相对纯聊天的收益，也不能据此宣称减少长期遗忘。[研究原文 §4–5](https://arxiv.org/html/2305.11483v2#S4)

### 接住当前问题与持续管理所有问题是两项工作

Agent 可能每一轮都给出相关回答，却没有持续辨认：

- 之前哪个问题还没答完？
- 新问题是在补充、替代，还是暂时打断旧问题？
- 一段讨论产生的是假设、阶段性结论，还是已经采用的决定？

例如，Agent 一次给出五个方向，用户选择第三个继续聊，其余四个方向的去向仍然需要明确。

模型使用旧信息的能力也可能叠加影响。《Lost in the Middle》在当时受测模型的多文档问答和键值检索任务中发现，相关信息的位置影响使用效果。这项研究没有直接测试问题追踪，也不能代表 2026 年所有模型或证明本次体验由上下文长度导致。[TACL 2024 原文](https://aclanthology.org/2024.tacl-1.9/)

### 自由讨论和整理过程需要不同的注意力安排

正在思考时，顺着新发现聊下去很自然。停下来分类、标记状态，会打断当下的思路；等到结束后再整理，又需要重新回看整个过程。

“重要”也未必等于“聊得多”。一句只出现过一次的疑问，可能比讨论了十轮的细节更值得保留。重要性还会随着目标和新证据变化，不能仅凭篇幅、出现频次或 Agent 的判断确定。

## 五、对 AI 协作实践的启示

基于以上分析，可以暂时把这个现象定义为：

> 在持续探索的对话中，用户希望保留的问题，逐渐失去了可辨认的身份、处理状态，或者再次进入讨论的线索。

这一定义带来三个判断：

1. **多话题可以是思考取得进展的表现。** 新问题可能意味着发现依赖、修正理解，或找到更值得追问的方向。
2. **未解决的问题也可以被合理搁置或放弃。** 损失发生在用户仍然希望保留或继续，却想不起、找不到，或者无法接着推进时。
3. **需要保留用户与内容的关系。** 例如：仍然在意的问题、暂时接受的判断、等待证据后继续的方向。

这里可讨论的管理单位是“问题及其状态”。其中，话题表示讨论范围，问题表示尚待回答的疑问，结论表示当前认识，决策表示采用的选择，待办表示需要执行的行动。它们可能互相转化，但一个新念头不应自动成为必须完成的任务。

聊天保存、摘要、搜索和分支分别覆盖内容留存、压缩、找回和路径分离。是否足以保留问题及其进展，需要另行检验。例如，CanvasConvo 中有人能够回到放下的分支继续讨论，但跨分支比较和整合仍然存在困难。[研究原文 §6.3.1](https://arxiv.org/html/2605.15848v1#S6.SS3.SSS1)

本文尚未选择具体界面、自动化程度或状态模型。可以先用三个结果判断后续探索是否解决了实际需要：

- 聊完后，能否知道自己发现了哪些值得保留的问题？
- 能否看出这些问题分别讨论到了哪里？
- 下次回来，能否直接接着推进？

## 六、下一步需要验证什么

从实际对话样本中，逐个找回用户认为遗失的关键问题，再检查：

1. 问题是否被表达过，最早出现在哪里？
2. 最后讨论到哪里，是否有回答、结论或明确搁置？
3. 哪次转向后没有再回来，当时为什么转向？
4. 用户后来需要的是原文、判断依据，还是继续工作的入口？
5. 这个问题现在仍值得继续，还是已经被新认识取代？

这些问题用于区分不同成因。现有研究支持分岔、回访与整合值得分别关注，但没有直接给出日常 Agent 对话中关键问题的长期遗漏率，也没有证明某一种产品形态能完整解决它。

## 研究来源

- [Sensecape: Enabling Multilevel Exploration and Sensemaking with Large Language Models](https://arxiv.org/html/2305.11483v2)，UIST 2023。短时、被试内系统比较，观察探索、组织与回访行为。
- [Conversations in Space: Structuring Non-Linear LLM Interactions on a Canvas](https://arxiv.org/html/2605.15848v1)，2026-05-15 预印本。24 人短期部署，包含问卷、访谈与日志，无随机对照；正文写 5 天，arXiv 摘要页写 5–7 天。
- [Interruptions create prospective memory tasks](https://onlinelibrary.wiley.com/doi/10.1002/acp.1441)，2009 卷期、2008 在线发表。本文使用已核验的出版社摘要，作为理解恢复意图的间接证据。
- [Lost in the Middle: How Language Models Use Long Contexts](https://aclanthology.org/2024.tacl-1.9/)，TACL 2024。历史模型的信息位置实验，作为理解上下文利用边界的间接证据。
