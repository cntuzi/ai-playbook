# 决策卫生（决策后数据清理 + 落盘前合理性自检）

> 一句话：决策不能只落到一次性记录里。**落盘前先合理性自检（防造脏），落盘后强制级联清理（清旧脏），否决也必须落盘（防负空间脏）。**
> 适用：任何项目。每次总结/复盘/决策时把它当默认检查项。
> 权威完整版（含案例/模板）在 MooX Web 项目 `methodology/dirty-data-governance/`（AI Native 方法论库孵化地，团队共享）；本文件是跨项目个人便携版，更新时与权威源同步。

---

## 0. 为什么需要（根因）

决策类脏数据 = 被否定/推翻的旧方向没及时清理，残留在文档里，反复污染后续判断——**连决策者本人都被污染**（在写满旧内容的环境里做判断，地基本身是脏的）。

`dirty-data-governance` 治的是产品数据层（前后端字段/术语/假 UI）；本 skill 治**决策/文档层**，并管**触发时机**（决策落盘那一刻）+ **预防**（落盘前自检）。

教训（2026-06-03 MooX Web）：独立库 / 单进程 / 自建鉴权被口头否定但**没落盘** → 旧文档原样留着 → 新产出照搬重现，连栽三次。根子：否决没落盘 + 决策后没清理 + 落盘前没做合理性审视。

---

## 1. 三个环节（按序）

### 环节 A — 落盘前：合理性自检（防造新脏数据）

产出/落盘前，对每个核心判断逐个问：

- 这**合理**吗？**必要**吗？有没有**更简单**的？**为什么不是 X**？
- 这个设计/字段/假设的**真实源**是什么？还是我从旧文档/直觉搬来的？
- 说不出"为什么必要、为什么不能更简单" → **危险信号**，大概率是搬来的脏数据，停下核实再写。

> 反例：写"独立物理库"时，只要问一句"内部为什么要再分库？隔离边界不是已经在别处了吗"——自己就发现是过度设计，不必等人纠正。

### 环节 B — 决策落盘（含否决）

- 决策写进 `decisions/`：背景 / 选定 / **否定了什么** / 理由 / 可逆性 / 验证。
- **否决必须立即落盘**：否决也是决策。口头否决不落盘 = **负空间脏数据**（grep 不到、无法被发现、必然反复重现）。
- 决策记录**必须含「级联清理清单」节**。

### 环节 C — 决策后：强制级联清理（清旧脏数据）

1. **识别**：这个决策**否定/改变**了哪些旧概念 / 旧字段 / 旧方向。
2. **全量扫**：grep 所有引用旧内容的文档（不发现一个清一个）。
   ```bash
   grep -rilE "<旧概念1|旧概念2|旧字段名>" specs decisions insights reports ai prd
   ```
3. **列清单**：`文档 + 脏内容 + 处理(改对/删) + 状态`，写进决策记录。
4. **清理**：用 `dirty-data-governance` 的方法精准清——改对或删；**留有效内容、不无脑删、不留"原来错的"记录节**；用 Edit 精准改不重写整文件。
5. **验证**：再 grep 一遍旧概念，确认无残留（残留必须是有意的历史引用）。

## 2. 与 dirty-data-governance 的分工（不重复）

| | dirty-data-governance | decision-hygiene（本 skill） |
|--|--|--|
| 治什么 | 产品数据层：前后端字段 / 术语 / 假 UI / 假功能 | 决策/文档层：被否方向残留 + 触发时机 |
| 触发 | "要清脏数据时" | "做完决策 / 否决 / 总结 / 重大产出时" |
| 清理方法 | 提供（5 类 / 5 步 / 决策树） | **引用它** |
| 独有 | 真实源契约、字段映射表 | 落盘前合理性自检、否决必落盘、决策后触发清理 |

---

## 3. 反模式

- ❌ **决策只落盘不清理** → 旧文档留着 = 脏数据反复坑人（含坑决策者本人）。
- ❌ **否决不落盘** → 负空间脏数据，grep 不到，必然重现。
- ❌ **机械搬旧文档/旧假设不做合理性自检** → 现造新脏数据。
- ❌ **清理时留"原来错在哪"的记录节** → 错误内容又成误导源（纠正留痕去 decisions/ 复盘，不在产品文档）。
- ❌ **清理无脑重写整文件** → 丢有效内容 / 改坏结构。用 Edit 精准清。

---

## 4. 检查清单（一个决策的 Done 标准）

- [ ] 落盘前对每个核心判断做了合理性自检（合理 / 必要 / 更简单 / 真实源）
- [ ] 决策已落盘 `decisions/`（含**否定了什么** + 理由）
- [ ] 否决也落盘了（不留口头）
- [ ] 决策记录含「级联清理清单」
- [ ] 全量扫了所有引用旧内容的文档（不是抽查）
- [ ] 逐个清理（改对 / 删），留有效、不留错误记录
- [ ] 再 grep 验证无残留

## 案例（示例 · MooX Web 2026-06-03）

- **决策**：后端形态（独立后端 + 多服务，否定单进程）/ NSFW 隔离（web↔native 后端边界，否定 web 后端内再分物理库）/ 鉴权（复用同一套 token，否定自建）。
- **脏数据源**：否决全是口头、没落盘；旧文档（`nsfw-isolation.md` / `implementation-design.html` / 五项决策）原样留着 → `backend-architecture.html` 照搬重现。
- **处置**：三决策 + 元规则落盘 decisions/；级联清理 5 份文档；合理性思考 + 决策后清理升进 `ai/principles.md`。

> 相关原则：项目 `ai/principles.md` 的「合理性思考」「文档一致性 + 决策后数据清理」「对齐真实优先」「文档只呈现正确状态」。本 skill 是这几条原则的执行流程。
