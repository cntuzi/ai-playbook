# 03 推导：AI 原生组织应该长什么样

> 前两份给了规律和理论，这一份把它们接起来，一步一步推到组织的形态。
> 最后用你现成的"付费复活"案例走一遍，看谁活、谁死。

---

## 第一步：从规律推出"必须有什么"

一条一条来，不跳步。

### 从规律 1（秩序要花钱维持）→ 系统必须会"输入 + 排出"

- 要有**学习/输入**机制：新的认知能进来；
- 要有**遗忘/清理**机制：过期的规则、能力、认知能被废弃。

> 只进不出的系统会烂掉。**遗忘能力和记忆能力同等重要。**

### 从规律 2（状态很贵）→ 状态必须精、可信、单一

- 一个事实只能有一份源，谁写谁管；
- 状态要能被校验、要标新鲜度；
- 冗余状态不是资产，是负债。

> **单一事实源**不是洁癖，是物理成本控制。

### 从规律 3（必要多样性）→ 验证闸是刚需

- 生成可以便宜、可以放开；
- 但进入"影响真实业务"之前，必须过验证闸，且验证的覆盖 ≥ 生成的花样。

> 验证不是可选项，是让 AI 靠谱的唯一硬约束。

### 从规律 4（信息会变脏）→ 一切认知都要带新鲜度

- 判断、规则、上下文都要有过期时间；
- 系统要主动清理过期认知，防止"过期地图"喂错路。

### 从 Coase（协调成本暴跌）→ 组织边界自由化

- 组织图不再是必须遵守的墙，而是可随时编译的配置；
- 围绕一个目标，可以临时组装执行主体，干完就散，认知沉淀下来。

### 从 Simon（近可分解性）→ 纵向自治 + 横向契约

- 领域内部强耦合（能力、规则、状态自洽）；
- 领域之间只通过稳定契约弱耦合。

### 从 VSM（五个子系统）→ 任何能干事的最小单元都必须有完整闭环

- 干活、协调、自检、看环境、定方向——五样缺一不可；
- 且这个结构**递归**：大组织是闭环，闭环里的小目标也是闭环。

---

## 第二步：合并成一句话

把上面七条压在一起，得到：

> **AI 原生组织 = 递归闭环 + 验证闸 + 人类决策点。**

展开就是每个目标跑一遍这个闭环：

```text
目标（Goal：要什么 + 怎么算成功）
  → 编译（Compile：结合当前状态和约束，编译成可执行合同）
  → 受界执行（Bounded Execution：agent 在权限和风险等级内干活）
  → 证据（Evidence：改了什么、对应哪条契约、跑了什么测试）
  → 验证（Verify：确定性检查 → 场景检查 → 人类判断，按风险分级）
  → 更新状态（Commit：业务事实更新、新规则进记忆、过期认知清理）
```

人不是组织里的一个"层"，而是闭环上的三个决策点：

1. **定目标和优先级**（定方向，VSM 的"政策"子系统）；
2. **裁决验证标准**（什么样算"对"，VSM 的"自调节"子系统升级人判）；
3. **批准不可逆动作**（发版、改配置、动钱、动线上用户）。

其余一切，可以是 agent。

## 第三步：用"付费复活"走一遍，看谁活谁死

**目标：** 高意愿玩家失败后能付费复活（提升关卡完成率 + 付费转化）。

**成功标准：** 一次支付最多产生一份复活权益；一份权益最多完成一次复活；旧客户端继续跑旧场景。

走闭环：

```text
Goal    复活场景：失败 → 支付 → 权益 → 恢复，可观察结果：关卡继续
Compile 引用不变量 INV-ENTITLEMENT-ONCE、契约 CTR-REVIVE-ENTITLEMENT，
        结合当前代码/数据现状 → 可执行合同
Execute agent 在"可改代码但不可动线上配置"的权限内实现
Evidence 改了什么、对应哪条契约条款、跑了哪些测试、哪些假设还没验证
Verify  领域回归（权益幂等）→ 契约测试（商业化↔可玩内容）→
        端到端（失败→恢复）→ 灰度/回滚演练 → 人类批准放量
Commit  业务事实更新为"已生效"、新规则进记忆、过期上下文清理
```

### 用判据给每个概念判生死

判据只有一句：**"闭环的哪一步、哪个组件会读它？它错了会坏掉什么？"**

| 概念 | 谁读它 | 判活 |
| --- | --- | --- |
| 不变量 INV | 编译时读、验证时校验 | **活** |
| 契约 CTR | 编译时读、验证时校验 | **活** |
| 场景 SCN | 验证的输入 | **活** |
| 变化 CHG（Before/After + 生效条件） | 编译的输入、Commit 的依据 | **活** |
| 证据 Evidence | Verify 的输入 | **活** |
| 风险分级 / 权限 | Execute 的边界、人类批准点 | **活** |
| 人类决策点 | 定目标、裁决验证、批不可逆动作 | **活** |
| Org 的角色/技能/Proficiency/Assignment | 闭环里没有任何组件读它 | **死**（那是给人建模的） |
| Ecosystem / Source / Environment 分类学 | 闭环里没人读 | **死** |
| "六个系统" 之类的扩展层 | 另一个抽象层的产物，不在本闭环 | **暂缓** |

### 对现有方法论的含义

**横纵 V1 要保住的**：五类对象（领域/能力/契约/场景/不变量）+ 变化 + 五层正确性。
它们不是文档，是**编译和验证的直接输入**——机器会读。

**要砍的**：Org 作为"人-角色-技能"的层级体系。它在 AI 原生下坍缩成两样：**权限/风险边界 + 人类决策点**。

**要重新定位的**：Spec。从"给人看的需求文档（Requirements→Design→Tasks→Verification）"退化成**一份合同**：目标 + 约束引用 + 验收标准。中间的 Design 和 Tasks 是 agent 运行时自己分解的，一次性，不值得沉淀。值得沉淀的只有：验证标准和执行后的证据。

**判据一句话**：不被执行闭环读取的模型，就是注定腐烂的文档。用这句话过一遍你的目录，很多分类学自然消失。

## 第四步：可开展（能动手的下一步）

不要再加理论。按下面顺序做，每步都能落地：

1. **选一个真实业务变化**（付费复活，或你们当前真正在做的），按上面的闭环写一份最小合同：目标 + 约束 + 验收标准。不写 Design/Tasks。
2. **把验证闸做成最小原型**：先把该变化的"不变量 + 契约 + 场景"列成机器可检查的清单，配一个自动检查脚本。这是整个系统里第一优先，因为它是硬约束。
3. **跑一遍**，记录：哪些概念被真实使用了，哪些没有。没有的砍。
4. **清理旧稿**：给 04 讨论稿里被否定的层级稿标注状态（被吸收/被否定），防止三套矛盾本体论继续污染讨论。

## 收尾

> 从物理规律（第二定律、Landauer、Ashby、香农）
> 到组织理论（Coase、Simon、阿吉里斯-肖恩、野中、Nelson-Winter、Beer VSM）
> 推导出的结论只有一个：
>
> **AI 原生组织不是一张组织图，是一圈递归的闭环。**
> 状态是闭环的原料，验证是闭环的闸门，人是闭环上做决断的三个点。
> 组织图可以自由配置——因为 AI 让协调成本暴跌了。
